# Driving a Physical iPhone with `turbotap`

Use `turbotap` to operate any app on a real iPhone over Wi-Fi without AirPlay screen mirroring, Bluetooth HID, or burning 20 seconds of LLM round-trip on every tap.

## 0. A Longer Task, Start to Finish (posting, installing, filling a form)

1. **Ready, bounded, one recovery.** `turbotap --device N preflight --require-ready` checks the lock state, front app, screen size and one small capture, and exits 1 with `not_ready` reasons. Do the one recovery it names (`turbotap unlock` once under the vault rule, or `turbotap deploy` once for an empty capture or no answer), run preflight once more, and stop with its reason if it is still not ready. Never loop on empty screenshots.
2. **The app before anything else.** `open:BUNDLE` (or `launch:`) first, before preparing media or text: it fails at once with iOS's reason when the app is missing, restricted or not opened, and succeeds only when the app was seen in front. Install a missing app first, then continue.
3. **Media: what is already there first, then only the allowed path.** Check the app's picker or Photos for the exact item (name, duration or date) and use it if it is there. Transfer only when it is not, and only over a path the task allows; never invent a new channel.
4. **Wait on the exact control, not the clock.** For anything slow (a download, an upload, a server reply), poll `ui` once a second against the control's own position or label with a hard deadline, and act in the same moment it appears, checking the exact target again right before the press. No fixed sleeps between checks, no hand-measured coordinate boxes.
5. **Receipt.** At the end, `turbotap --device N timings --receipt --since START --until END` splits the wall clock into the helper between steps, WDA, app wait and turbotap, with retries, failures and the longest gaps. Put it in the report: it shows where the minutes went.

### Compose a draft (a post, a message, a form) in few turns

Each turn costs seconds of thinking, so do each phase in ONE `flow` call and read only what the next decision needs.
1. **Open the composer:** `open:APP`, the create/compose control, then `ui` in the same flow.
2. **Destination first** (community, channel, recipient), then `ui` again: the destination can change the composer (rules banners, required fields, which attachment types exist). Check here whether the attachment you need is offered at all; if not, say so instead of searching for it.
3. **Attachment next**, if offered: pick the exact item (name, duration, date) in the picker in one flow.
4. **Text last, each field in one flow:** `tap:<field>` then `type:<text>` (or `cleartype:`). Long text (120+ characters) is typed at 200 chars/s with a 24-character probe checked in the focused field and a read-back at the end (a field that reports no value: typed on, result `unverified`); if it says the text "did not land" (the field moved, e.g. under a banner or the keyboard), tap the field again and retype only then.
5. **Verify in one flow:** `banner:dismiss assertfield:<title field>=file:TITLE.txt assertfield:<body field>=file:BODY.txt read` clears a notification banner first, checks the exact text (blank lines included) and shows destination and attachment. A field whose placeholder disappears once text is in can be named `#N` (the Nth text input from the top; an error lists them with their y); when WDA reports no value for it, the check reads the field's frame by OCR (visible lines, whitespace-insensitive).
   With several rows of the same label (repeated chips or list rows), `tapat:X,Y=LABEL` presses the one nearest X,Y.
6. **Stop at the draft.** Never press the composer's submit control (Post, Send, a top-bar Next in a filled composer) unless the user asked to publish.

## 1. Core Speed Rules (Read Before Running Anything)

1. **Bundle steps into ONE `turbotap flow` command.** Never split `open:APP` and `tap:...` across LLM turns — each extra turn costs 15–25 s while a local `flow` step takes ~200–350 ms (session settings and screen size are cached per device in `~/.cache/turbotap/`).
2. **Drop `home` before `open:APP`.** `open:APP` brings any app straight to the foreground (~100 ms); `home` wastes ~500 ms.
3. **Use `open:APP` vs `launch:APP` deliberately:** `open:` resumes where the app was; `launch:` terminates and cold-starts it (use when an app must fetch fresh state or a pending approval prompt). Both wait for the target app to become active before reading or tapping, so `ui` and `read` right after `open:` won't return the previous app's controls.
4. **Skip tapping an already-selected tab.** `tap:` checks for a real UI reaction (global shift, local box diff, or localized change like a keypad digit) and never replays the same tap blindly when pixels don't change (avoiding double-actions on keypads/toggles/submissions; only a distinct nearby Switch or input control is promoted).
5. **Many separate `turbotap` calls in a row? Start the warm daemon.** `turbotap daemon start` binds in milliseconds and warms libtesseract engines and the WDA keep-alive connection on a private Unix socket (`~/.cache/turbotap/daemon.sock`, mode 0600, exits after 15 idle minutes). Then pass `--daemon` (or export `TURBOTAP_DAEMON=1`): an OCR command drops from ~555 to ~288 ms on a real iPhone (~2 ms local dispatch overhead). Each call still gets its own session checks, frames and app-switch state; without a running daemon the command simply runs in-process. Still prefer one `flow` over many calls.
6. **Poll with `wait:TEXT` or `gone:TEXT`, not `sleep:` or `tapel:`.** After `open:` on heavy/React Native apps, WDA element queries can stall while the tree builds. `wait:TEXT` is OCR-first (~180–250 ms) and falls back to the accessibility tree after 2 frames (~0.4 s) for low-contrast or colored buttons (e.g. green-on-dark `Start`). `gone:TEXT` polls until a spinner, sheet, or banner disappears.

## 2. Reading Screens (`read` vs `read:ocr` vs `read:vision` vs `read:Y0-Y1` vs `readel:` vs `ui`)

- **`read`** (default when exploring): settles OCR lines and returns **both** `lines` (OCR text + `(x, y)`) and `ui` (on-screen interactive controls: `Button`, app keypad `Key` with soft-keyboard keys filtered out, `Tab`, `Cell`, `SearchField`, `TextField`, `SecureTextField`, `TextView`, `Switch`, `Slider`, `PickerWheel`, `Image`, plus `value` on switches/sliders/fields/picker wheels and `"enabled": false` on disabled controls). Prunes off-screen recycled cells, internal CamelCase/asset images, decorative row chevrons, duplicate `(Cell, Button)` pairs, and invisible Unicode bidi/space chars.
- **`read:ocr`** (fastest full screen, ~180–250 ms cold, ~50–65 ms cached): OCR only, skips `/source`.
- **`read:vision`** / **`read:vision:fast`** (wda-turbo v6): Apple Vision OCR on the iPhone itself. Use it when host OCR misses text: non-Latin or mixed scripts, small or stylized fonts, light-on-dark rows. Accurate mode (default, 0.5× direct capture) read 72/72 words on a multilingual page at ~235 ms, against 12/72 for host OCR; `:fast` takes ~140 ms but reads much less. Returns `lines` in points like `read:ocr`, tagged `"engine": "vision"`. On stock or older runners the step fails with a clear message (no silent empty read); run `turbotap deploy` or fall back to `read:ocr`. Standalone: `turbotap vision-ocr [--mode accurate|fast] [--scale 0.5]`.
- **`read:Y0-Y1`**: OCR a vertical band only (points) — 3–4× faster than full-screen OCR when verifying a known header, banner, or result strip.
- **`readel:TEXT`**: polls the lightweight accessibility tree for labels containing `TEXT`. Best for stylized fonts, white text on photos, or split digits (e.g. 2FA codes where the `Cell` label is exact and includes the countdown).
- **`readfield:FIELD` / `assertfield:FIELD=VALUE`**: the exact value of one text input, named by its label, accessibility identifier or placeholder (exact beats substring; several matches fail and list them). Use these to prove what a form holds: `ui` has no text-view values, the tree drops blank lines and OCR sees only visible lines. `readfield:` returns the value with every newline (also in `reads`); `assertfield:` compares against text, `file:PATH` (one trailing newline ignored) or `env:VAR`/`cmd:CMD`, and on a mismatch says the lengths and where the first difference is. Read-only. A secure field is only ever reported by its length, so `assertfield:` on it passes on length alone (iOS exposes only bullets); a secret value never appears in output or the timing log. Don't `readfield:` a plain text field that may hold a credential (a password typed into the wrong field, a one-time code): it returns the value. An input hidden under the keyboard can be missing from the tree: close the keyboard first.
- **`ui`**: dumps all on-screen labelled controls with `(x, y)` (~250–450 ms via trimmed `/source` `excluded_attributes`).

## 3. Targeting & Navigation Patterns

```bash
# Multi-step examples (one process, 2-6 s total)
turbotap flow open:Spotify tap:"Your Library" tap:"Liked Songs@y>150" wait:songs read:ocr tap:Back
turbotap flow open:Messenger wait:"Ask Meta" tap:"Alice@y>300" read tap:Back
turbotap flow open:Instagram tapel:"Direct messages" tap:"Bob@below:Messages" read
turbotap flow open:Safari tap:Address type:https://example.com key:return gone:Loading read:0-240
turbotap flow open:Authenticator readel:OpenAI
turbotap flow open:Messenger search:Alice wait:'re:Alice\s+Smith'
```

- **Exact labels, enabled state & status bar:** `tap:TEXT` prefers enabled controls over disabled ones (e.g. a dimmed `"New Note"` button), and prefers an exact Button/Key/Link label over a longer OCR line (`tap:"Sign In"` won't hit `Sign in with another account`; `tap:2` hits the `Key` over `"1 2 3"`). In-app matches automatically beat iOS status-bar hits (`y < 54`) unless explicitly targeted with `@y<...`/`@above:...`. Tapping a switch row's label that doesn't react flips the toggle itself; `Next`/`Previous`/`Neste`/`Forrige` pick the form's button over the keyboard toolbar's copy.
- **Failed steps show exact labels:** a failing `flow` returns `visible` (OCR lines) and `ui` (top 30 interactive controls with exact labels and `(x, y)`). Retry with those; don't spend a turn on `tree`.
- **Region filters, batch taps, assertions & regex (`@below:HEADER`, `@above:HEADER`, `@y>N`, `@y<N`, `tapbatch:`, `assert:`, `assertnot:`, `re:REGEX`):** Disambiguate repeated labels with regions (`tap:"Alice@below:Chats"`, `tap:"Alice@y>300"`). Works in `tap:`, `tapif:`, `tapbatch:`, `toggle:`, `longpress:`, `doubletap:`, `swipe:left|right:`, `wait:`, `waitany:`, `assert:`, `assertnot:`, and `scrollto:` (including icon-only accessibility controls). `assert:TEXT` / `assertnot:TEXT` perform fast single-frame non-mutating presence/absence checks across both OCR and UI controls. OCR matching automatically folds Unicode/Nordic diacritics (`å`↔`a`, `ø`↔`o`, `æ`↔`ae`, `é`↔`e`, etc.) when exact diacritics are missed by Tesseract, while exact diacritics always win at the same rank. Use `tapbatch:A,B,C` (`\,` for literal comma) to validate all labels and `--deny` upfront and re-resolve live UI between taps, or `tapbatch:fixed:A,B,C` for known stationary keypads (e.g. Calculator) to dispatch in ~600 ms via one `/wda/fastTapBatch` call. Use `re:REGEX` for dynamic text (`wait:'re:\d+ results?'`).
- **Optional dismissals (`tapif:TEXT`) & branching waits (`waitany:A|B|C`):** `tapif:TEXT` taps optional sheets/banners within ~1 s (OCR + exact UI control fallback, respects `--deny` and `@region`) or returns `"skipped"` without failing (`tapif:"Not Now"`, `tapif:Skip`). `waitany:A|B|C` polls OCR-first (then UI controls + targeted Sauvola fallback, per-candidate `@region` supported) until any `|`-separated target appears and returns the matched text (`waitany:"Open|Get|Update"`).
- **Icon-only, colored & keypad controls:** `tap:TEXT` falls back to exact accessibility labels (`Button`, `Key`, etc.) when the first OCR frame misses `TEXT`; `wait:TEXT` falls back to `ui_controls(text=True)` after 2 frames (~0.4 s) for low-contrast/colored buttons. Use `tapel:LABEL` directly when you already know an icon-only or localized keypad label (e.g. calculator operators).
- **Label tap with a location hint (`tapat:X,Y`):** when you picked a spot from a screenshot, use `tapat:X,Y` instead of a `read` plus `tap:LABEL`. It finds the labelled accessibility control nearest that spot (within 24 pt; controls only, never OCR text), checks its label against `--deny` and the app guard, and taps that control's own centre, never the raw point, all in one step. The resolved label is the step's result and is written to the timing log. With no labelled control there it is refused and lists the nearest labels with their positions. When you already know which label must be pressed, use `tapat:X,Y=LABEL`: it presses only an enabled control labelled exactly LABEL there, read fresh: the one nearest X,Y when several have that label (a control listed twice is pressed once), and refuses with nothing pressed if none is labelled LABEL any more, it is disabled, or two are equally near at different places. Bare `tapat:X,Y` presses whatever labelled control is nearest now. Because it always taps a labelled target, it counts as a label tap, not a coordinate tap, and is allowed where coordinate taps are banned. `tapxy:` taps the raw point and is not guarded; don't use it for buttons.
- **Long-press, double-tap & pinch-zoom (`longpress:`, `doubletap:`, `zoom:`):** `longpress:TEXT` / `longpressxy:X,Y[,MS]` holds ~0.65 s (via `/wda/fastTap` duration or stock `/wda/touchAndHold`) for context menus/action sheets. `doubletap:TEXT` / `doubletapxy:X,Y` runs a single-record double-tap via `/wda/fastDoubleTap` (fallback: `/wda/doubleTap`). Both support `@region` and `--deny`. `zoom:in|out|SCALE[@X,Y]` runs a clamped two-finger pinch/zoom via `/wda/fastPinch` (default screen center, `in=2.0`, `out=0.5`, fallback: stock `/wda/pinch`).
- **Direct URLs, switches & sliders (`url:`, `toggle:`, `slider:`):** Use `url:https://...` (or `maps://`, `mailto:`, `tel:`, `sms:`) to open a URL/deep-link directly via `/url` (~110–330 ms vs ~3 s typing in Safari). Use `toggle:LABEL=on|off` (supports `@region` and `--deny`) to idempotently set an iOS `Switch` — skips tapping if already in the desired state and verifies state after tapping. Use `slider:[LABEL=]PCT` (`50%` or `0.5`, respects `--deny`, rejects disabled sliders) to set an `XCUIElementTypeSlider` directly.
- **Back navigation, scrolling & swipes (`back`, `scroll:`, `scrollto:`, `swipe:`):** `tap:Back` checks for a lone `<` nav chevron (`x < 70, 55 < y < 130`) before touching `/source`; `back` edge-swipes and falls back to tapping Back. `scroll:down|up`, `scrollto:TEXT`, and `scrollto:up:TEXT` use zero-momentum `/wda/fastDrag` (~150–370 ms settle) and reuse settled OCR lines for an immediate follow-up `tap:TEXT`. `scrollto:TEXT` without a direction turns at the end of the list and searches back up, so you don't need a second `scrollto:up:` call; give `up:`/`down:` only to scroll one way. `swipe:left|right|up|down` runs a fast mid-screen swipe (carousels/tabs/pull-to-refresh). `swipe:left:TEXT` / `swipe:right:TEXT` finds `TEXT`'s row and runs a damped partial drag (80%→30% / 20%→70%) to reveal row actions (Archive/Delete/More) without triggering full-width destructive delete; tapping a revealed `Delete` button remains gated by `--deny`.
- **Search bars & picker wheels (`search:QUERY`, `picker:[INDEX:]VALUE`):** `search:` finds the `SearchField` (or Search tab/button + field), types via `/wda/keys`, and settles without pressing Return. `picker:VALUE` (or `picker:1:30` for multi-wheel date/time pickers) sets a `PickerWheel` directly via WDA element value.

## 4. Forms, Auth, PIN Pads & Tricky iOS Edge Cases

- **Typing & control keys (`type:`, `key:`):** `type:` automatically waits for brief keyboard focus after tapping a `TextField`/`SearchField`/`SecureTextField`/`TextView` (no manual `sleep:` needed). Use `key:return|backspace|tab|space|escape` for control keys instead of escaping `\n` in the shell (for inline newlines in `type:`, use ANSI-C quoting `$'type:line1\nline2'`, since `"type:...\n"` sends literal `\n`).
- **Long text (`type:`/`cleartype:` with 120+ characters):** typed at 200 chars/s (set `TURBOTAP_TYPING_FREQ` for another rate) after a 24-character probe checked in the focused field's value, then read back. A probe missing from a field that reports its value stops the step with only those characters sent; a field that reports no value is typed into and the result says `unverified` (check it with `readfield:`/`read`).
- **Named fields (`fill:FIELD=VALUE`): use it for forms and long text.** `fill:` finds the one input whose label, accessibility identifier or placeholder is FIELD (same matching as `readfield:`), clears it, focuses it and confirms a keyboard came up (if the element click brings none, it taps inside the field's own frame; some custom text views only focus that way), types at 200 characters per second (about 7 s for 1,400 characters instead of 23 s at XCTest's default; `TURBOTAP_TYPING_FREQ` overrides) and reads the value back exactly. VALUE is text, `file:PATH` for exact multi-line text (paragraphs and blank lines survive; one trailing newline dropped), or `env:VAR` / `cmd:CMD` for secrets. For a secret, a secure field or text of 40+ characters it first proves focus with one probe character that must land in that field (then deletes it), so nothing is typed blind; secrets and secure fields are checked by length and never printed. A field that dropped out of the tree under the keyboard is looked for again after a short downward drag closes the keyboard. It types into the field it names, even if the layout moved (a banner above it), because it targets the element, not a coordinate.
- **WebView & editable fields (`cleartype:TEXT` + `dismisskb`):** iOS WebViews often append instead of replacing. `cleartype:` supports `TextField`, `SecureTextField`, `SearchField`, and `TextView` (plus `env:VAR` / `cmd:CMD` for secrets), clearing, typing via `/wda/keys`, and verifying read-back on non-secure fields. Follow with `dismisskb` (one localized predicate matching `Done`/`Ferdig`/`Hide keyboard`/`Skjul tastatur`/`Dismiss`/`Lukk`) before submitting.
- **Formatted numeric inputs (`typedigits:VALUE|env:VAR`):** Clears the field, types 1 digit every `0.08 s` via `/wda/keys`, strips formatting on read-back, and asserts an exact digit-by-digit match (retrying once on mismatch) so WebView formatters never drop digits.
- **Installs and other long operations:** an install or download button usually turns into progress and then into the control that opens the result; wait for that control with the recipe below. Enter a password only into the focused secure field: tap that field first, use `type:env:VAR`/`type:cmd:CMD`, then check with `ui`.
- **Waiting for a control that takes long to appear:** poll the accessibility tree once a second with a hard deadline and press the moment the exact control is there, instead of fixed sleeps between checks or hand-measured coordinate boxes. `ui` takes about 0.2 s and no screenshot, so a 1 s cadence is cheap; `wait:` grabs frames continuously and suits waits of seconds, not minutes. The caller supplies the device, the app the control belongs to, the deadline and the target's exact label as the live tree shows it (any language), plus, when the label can appear more than once, the position where this control will appear:

  ```sh
  DEV=...; APP=...; LIMIT=...   # turbotap device, bundle id of the app the control belongs to, deadline in seconds
  LABEL=...                     # the target's exact label as the screen shows it, in its language (or an identifier the app exposes as its label)
  X=; Y=                        # optional: where the control will appear (its position in `ui`); empty = anywhere, but then only one may match
  end=$((SECONDS + LIMIT)); last="nothing"
  tt() { TURBOTAP_ALLOWED_APPS="$APP" timeout "$1" turbotap --device "$DEV" "${@:2}"; }
  sel='.reads[-1].ui[]? | select($x == "" or (((.x - ($x | tonumber)) | fabs) <= 24 and ((.y - ($y | tonumber)) | fabs) <= 24))'
  while :; do
    left=$((end - SECONDS)); [ "$left" -gt 0 ] || { echo "'$LABEL' did not appear within ${LIMIT}s; last seen: $last" >&2; exit 1; }
    out=$(tt "$left" flow --quiet --allow-app "$APP" ui); rc=$?
    if [ "$rc" -ne 0 ] || [ "$(jq -r '.ok' <<<"$out" 2>/dev/null)" != true ]; then
      echo "ui failed (rc $rc), stopping" >&2; exit $((rc ? rc : 1))   # 6 = stop file, 1 = app guard or other refusal
    fi
    a=(--arg l "$LABEL" --arg x "$X" --arg y "$Y")
    last=$(jq -r "${a[@]}" "[$sel | .label] | .[0:5] | if length == 0 then \"nothing\" else join(\", \") end" <<<"$out")
    hits=$(jq -c "${a[@]}" "[$sel | select(.label == \$l and .enabled != false)]" <<<"$out")
    case $(jq length <<<"$hits") in
      0) ;;
      1) left=$((end - SECONDS)); [ "$left" -gt 0 ] || left=1
         front=$(tt "$left" preflight | jq -r '.active_app // empty' 2>/dev/null)
         [ "$front" = "$APP" ] || { echo "'$front' is in front, not $APP; not pressing" >&2; exit 4; }
         px=$(jq -r '.[0].x' <<<"$hits"); py=$(jq -r '.[0].y' <<<"$hits")
         res=$(tt "$left" flow --quiet --allow-app "$APP" "tapat:$px,$py=$LABEL"); rc=$?
         if [ "$rc" -eq 0 ] && [ "$(jq -r '.ok' <<<"$res" 2>/dev/null)" = true ]; then echo "pressed '$LABEL' at $px,$py"; exit 0; fi
         echo "press refused or failed (rc $rc); nothing pressed if the control changed" >&2; exit $((rc ? rc : 1)) ;;
      *) echo "several enabled '$LABEL' controls match; not pressing (give X,Y)" >&2; exit 3 ;;
    esac
    sleep 1
  done
  ```

  Every call carries the app guard for that app and is bounded by the remaining budget. A failed `ui` stops at once with its exit code (6 = stop file, 1 = app guard or another refusal). Several enabled matches stop without pressing. Right before the press it checks that the app in front is exactly that app; the press is `tapat:X,Y=LABEL`, which re-reads the screen and presses only the one enabled control with exactly that label there, so a control that changed since the read is refused with nothing pressed. Only exit code 0 with `"ok": true` counts as pressed; on the deadline it reports what it last saw.
- **`FLAG_SECURE` PIN pads (`pintap:DIGITS|env:VAR|cmd:CMD`):** Dismiss any Face ID sheet first (`alert:accept` or `tap:Cancel`), then run `pintap:env:APP_PIN` — reads `XCUIElementTypeKey` rects from `/source` and taps via `/wda/fastTapBatch` (conservative 150 ms inter-key spacing in one XPC call, with automatic fallback to sequential `/wda/fastTap` on older/stock WDA).
- **Clipboard (`clipboard`, `setclip:TEXT|env:V|cmd:C`):** `clipboard` (alias `copy`) reads the iOS pasteboard via `/wda/getPasteboard`; `setclip:` writes UTF-8 text via `/wda/setPasteboard` (use `env:`/`cmd:` for secrets). *iOS 16+ caveat:* `setclip:` writes from the WDA runner, so pasting into another app may trigger an iOS `"Allow Paste"` banner unless previously allowed for that app.
- **Unlocking an authorized device:** Use `turbotap --device NAME unlock` with a configured `passcode_cmd` or a securely supplied `WDA_PASSCODE`. Keep the passcode out of output and logs. If an attempt fails, stop rather than retrying.
- **System alerts, lock screen, idle Wi-Fi & SMS OTPs:** `alert:accept|dismiss|text` accepts, dismisses, or reads an active iOS system alert (`read` and `ui` also detect active SpringBoard alerts right after `open:`/`launch:` immediately without stalling in stale-app retries, surfacing alert buttons and attaching `"alert"` to `read`); `unlock` uses screen-size-agnostic `XCUIElementTypeKey` clicks (`WDA_PASSCODE` or `passcode_cmd`); idle iOS Wi-Fi wakes with one ICMP ping on first `/status` timeout; `turbotap otp-type --pattern '%code%' --after-rowid <N>` polls macOS `Messages/chat.db` (read-only) over SSH and types paced OTP digits.

## 5. Safety & Anti-Double-Send Rules

- **App guard (`allowed_apps`, `--allow-app`):** When `~/.config/turbotap/config.json` has `allowed_apps` (per device under `devices.<name>`, else top-level) or `TURBOTAP_ALLOWED_APPS` is set, every input step (taps, typing, swipes, scrolls, toggles, sliders, pickers, `setclip:`, `alert:accept|dismiss`, `tap-ocr`, `otp-type`) checks the live foreground app first and is refused (exit 1, nothing sent) unless it is on the list; an unknown foreground app is refused too. Start flows with `open:<allowed app>` (allowed from the Home Screen; opening an unlisted app is refused). `url:` is refused while the guard is on (iOS picks the receiving app); use `open:` and navigate. For an app's own custom scheme (a pairing link like `myapp://pair?...`), pass `--allow-url-scheme myapp` together with `--allow-app BUNDLE` for that run instead of going around turbotap (no `devicectl --payload-url`): `url:` then opens only that exact custom scheme (never http, https, tel, sms, mailto or other system schemes), only while a live check confirms the `--allow-app` app is in front, and if another app comes to the front afterwards the run stops before any further input. The stop file still wins; only the scheme is logged, never the URL. On a shared test phone, opening a URL (and so touching another app's state) needs the phone owner's go before each use, even with the flag. A broken `config.json` blocks all input until fixed, and so does a `--device` that does not match the `--url`/`WDA_URL` endpoint (prefer `--device NAME` alone). If you are refused, you were about to type into the wrong app: re-check with `preflight` and `open:` the right app. Add `--allow-app BUNDLE_ID` only when the user asked you to work in that app; it lasts one run. `--no-deny` never disables this guard.
- **Stop file (exit 6):** If `turbotap` exits with code 6 and says a stop file exists, the user has frozen the phone: stop, do not retry, do not delete or move the stop file, and tell the user. Configured with `stop_file` in config.json or `TURBOTAP_STOP_FILE`. It is checked when each `turbotap` command starts and again right before every input and between flow steps, so creating it during a running flow stops that flow before its next input (exit 6). A shell loop around `turbotap` must still end on exit 6 instead of polling on, and long waits should stay bounded (a read-only wait sees the stop only at its next step).
- **Built-in `--deny` guard:** Taps and long-presses matching destructive/external labels (`send`, `pay`, `buy`, `subscribe`, `delete`, `unsend`, `remove`, `cancel booking`, `start audio/video call`, `record voice`, `accept/decline/maybe`) are refused by default. With the app guard on and an allowlisted app confirmed in front, a control labelled exactly `Send` or `Send message` is allowed without `--no-deny` (any other label, such as `Send payment` or `Send attachment`, and pay, buy, delete, cancel booking and calls stay refused); without an allowlist it is refused as before. Prefer that over `--no-deny`, which turns the whole filter off: only pass `--no-deny` when explicitly authorized for that exact action. As of v1.5.6 the filter checks the labels of tapped controls only: `key:return` and a newline inside `type:` are not checked, and in a field whose Return key reads `Send` (or submits a form) they send. Tap the labelled control instead.
- **Custom `--deny` (as of v1.5.6):** the built-in words are English. For a phone in another language, the caller supplies that language's destructive words: preferably with `--deny-also REGEX` (repeatable) or `"deny_also"` in config.json (per device or top-level), which **add** to the built-in pattern or an explicit `--deny`, are never relaxed, and also make `key:return` and multi-line text refuse when a keyboard key's label matches them (a newline may submit; an explicit `--deny` match there only warns; `--no-deny` drops them, with a warning). The older way is `turbotap flow --deny REGEX ...` (per call). `--deny` **replaces** the built-in pattern, it does not add to it: a pattern with only the extra words drops every built-in protection, and `--deny ''` turns the filter off like `--no-deny`. Any explicit `--deny`, even one equal to the built-in pattern, is never relaxed, so the plain-Send exception and `--allow-label` do not apply with it. The pattern is case-insensitive and matched against the target's label and accessibility name. To keep the baseline, compose it with the built-in pattern of your installed version (`DENY_DEFAULT` in `src/flow/mod.rs` at its tag), each part in its own group:

  ```sh
  BASE='...'                       # DENY_DEFAULT of the installed turbotap version, copied exactly
  EXTRA='\bwordone\b|\bwordtwo\b'  # the phone language's destructive words, supplied by the caller
  turbotap flow --deny "(?:$BASE)|(?:$EXTRA)" open:App tap:...
  ```

- **Plain Send on icon buttons:** the plain-Send exception also covers a button labelled exactly `Send`/`Send message` whose accessibility name is an icon-style identifier (`arrow.up`, `paperplane.fill`, `sendButton`) with no money, delete, call, all/everyone or attachment word in it. When a Send is refused, the error says why (the element's label and name, and the foreground check), so read it before reaching for anything else.
- **Send menus and other "send" labels (`--allow-label`):** a control whose label contains "send" but isn't a plain Send (`Choose how to send while the agent is working`, and menu items after it like `Send now`) stays refused by default. When the user asked for that exact action, pass each exact label with `--allow-label "EXACT LABEL"` together with `--allow-app BUNDLE` for that run. It only lets through a control whose own label is exactly that text, only if "send" is the only deny word in it and it contains no money, destructive, call, all/everyone, attachment or confirmation word (Send payment, Send money, Send to everyone, Delete, calls and the rest stay refused), and only while a live check confirms the `--allow-app` app is in front. No patterns: every menu item needs its own `--allow-label`. Never reach for `--no-deny` instead (it turns the whole filter off; `--allow-label` has no effect with it and prints a warning); an explicit `--deny` is never relaxed; the stop file still wins. Each use is printed to stderr.
- **NEVER retry an external `Send`, `Pay`, or `Submit` based on OCR alone.** Dark-mode or colored outgoing bubbles are often missed by grayscale OCR even when the send succeeded. Always capture `shot:PATH` (a private directory: screenshots show the user's messages) and inspect it (or check `ui`) before retrying.
- **Secrets go only into the field meant for them.** `cleartype:env:VAR`/`cmd:CMD` types a secret into the secure (password) field on screen, or the focused one of several; with no secure field, into the focused or only text field (a one-time code). The secret is written through that element (WDA element value), not sent to whatever has focus, so a popup or autofill that moves focus cannot redirect it. It refuses (nothing sent) when the target is ambiguous or never gets keyboard focus; `type:env:`/`cmd:` writes through the focused element only when focus is known and is the password field (or, with no password field, a text field), and refuses otherwise. If part of the secret still turns up in another field, that field is cleared and the step fails without echoing it. After such a failure, look at the screen with `ui` before any retry; do not take a screenshot or `read` first.
- **Never print secrets** (passcodes, PINs, passwords, OTPs, national IDs) in logs, chat, or shell arguments — pass them through `env:VAR` or `cmd:...`.

## 6. Timing log (`turbotap timings`)

`turbotap --device N timings --receipt --since START [--until END]` gives one run's receipt: `wall_ms`, `split_ms` (`helper_between_steps`, `wda`, `app_wait`, `turbotap_own`, which add up to the wall clock), `retries`, `failures` and `longest_gaps` (the step before and after each). Large `helper_between_steps` is time between turbotap calls (agent thinking, shell sleeps, other tools), not turbotap.

Every flow step and standalone command appends one JSON line to `~/.local/state/turbotap/timings.jsonl` (`TURBOTAP_TIMINGS=PATH` moves it, `TURBOTAP_TIMINGS=0` turns it off): step, safe argument (never typed text or credentials), `ms`, `wda_ms` (time in WDA requests), `sleep_ms`, `wda` round trips, `shots`, `tree` queries, bytes, `retries`, `req_ms` (time per request kind, to see where a step's time went), `target` (what a tap resolved to), app and ok/error. `turbotap timings --since 1h --by step|app|step+app` prints p50/p95/max per group plus the slowest and most retried steps. Use it after a session to find what to fix (see `turbotap-retro`).
